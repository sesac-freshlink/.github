# common v0.1.0 · v0.1.1: 쪽지 DTO와 공통 오류 응답

> 담당: 김진아 · 갱신: 2026-10-30 · 상태: 현재 · 태그: v0.1.0, v0.1.1 (2026-10-16)

## 1. 한 줄 요약

서비스끼리 SQS로 주고받는 쪽지 7종과, 모든 서비스가 같은 모양으로 내는 오류 응답을 한곳에 만들었다.

## 2. 왜 필요했나

inventory, order, logistics-simulator가 쪽지 클래스를 각자 만들면 필드 이름이나 날짜 형식이 어긋나 서로 못 읽는다. 오류 응답도 서비스마다 모양이 다르면 프론트가 서비스별로 따로 처리해야 한다. 그래서 한 번만 만들고 같은 버전을 가져다 쓰게 했다.

## 3. 바뀐 것

**쪽지 DTO** (`com.freshlink.common.message`)

| 큐 | type | 보내는 곳 |
| --- | --- | --- |
| `inventory-commands.fifo` (그룹 = storeId) | INBOUND | logistics-simulator |
| | RESERVE, CONFIRM, RELEASE | order-service |
| | DISPOSE | inventory-service |
| `inventory-results` | RESERVED, RESERVE_FAILED | inventory-service |

- 모든 쪽지는 JSON이고 `messageId`(UUID), `type`, `createdAt`(`+09:00`)을 가진다. 팩토리 `of(...)`가 이 셋을 채운다.
- `MessageJson.fromJson(body)`로 읽으면 `type`에 맞는 클래스가 나온다. 모르는 필드는 무시한다.
- 유통기한에 날짜만 오면 그날 23:59:59 한국 시간으로 읽는다.
- 패키지는 큐 기준으로 `command`(inventory-commands로 가는 것), `result`(inventory-results로 가는 것), `json`으로 나눴다.

**공통 오류 응답** (`com.freshlink.common.error`)

- `ErrorCode`(서비스마다 enum으로 구현), `BusinessException`, `ErrorResponse` `{"code", "message", "traceId"}`
- 처리기(`GlobalExceptionHandler`)는 common에 두지 않고 각 서비스에 둔다. 서비스마다 오류 목록이 다르고 Spring 웹 의존성을 common에 넣지 않기 위해서다.

## v0.1.1: RESERVED에 productName

RESERVED 쪽지에 `productName`이 생겼다. order가 주문 시점 상품명을 저장해 두고 점주 주문 목록과 결제창 주문명(`orderName`)에 쓴다. 팩토리 순서는 `of(orderId, storeId, productId, productName, quantity, unitPrice, lots)`다.

## 4. 쓰는 서비스가 할 일

- `build.gradle`에 GitHub Packages 저장소와 `com.freshlink:common` 의존성을 넣는다. PC에는 `GITHUB_ACTOR`, `GITHUB_TOKEN`(read:packages) 환경 변수가 필요하다.
- 서비스마다 `ErrorCode` enum과 `GlobalExceptionHandler`를 만든다 ([백엔드 공통 규칙](../../규칙/백엔드-공통-규칙.md) 6장).
- v0.1.1: inventory는 RESERVED를 보낼 때 상품명을 채우고, order는 받아서 저장한다.

## 5. 배포 순서와 주의할 점

v0.1.1은 필드를 더한 것뿐이라 순서가 상관없다. 옛 버전은 `productName`을 무시하고 읽는다.
