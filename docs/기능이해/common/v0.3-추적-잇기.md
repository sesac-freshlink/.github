# common v0.3.0: Outbox 추적 잇기

> 담당: 김진아 · 갱신: 2026-10-30 · 상태: 현재 · 태그: v0.3.0 (2026-10-20)

## 1. 한 줄 요약

주문 요청 → RESERVE 쪽지 → inventory 처리가 Zipkin·Grafana에서 **traceId 하나**로 이어져 보이게 했다.

## 2. 왜 필요했나

Outbox 발행기는 요청과 다른 스레드에서 쪽지를 보낸다. 그래서 그냥 두면 SQS 너머의 처리가 새 traceId로 시작하고, 주문 하나가 어디서 느려졌는지 한 화면에서 볼 수 없다.

## 3. 바뀐 것

| 언제 | 하는 일 |
| --- | --- |
| `OutboxWriter.save` | 지금 요청의 추적을 W3C `traceparent`로 `outbox.trace_parent`에 적는다. 추적 중이 아니면 NULL |
| `OutboxPublisher` 전송 | 그 값을 부모로 `outbox publish` 구간을 열고, SQS 메시지 속성 `traceparent`를 붙인다. NULL이면 예전처럼 보낸다 |
| 받는 쪽 `@SqsListener` | Spring Cloud AWS가 `traceparent`를 읽어 같은 추적을 잇는다 |

새 패키지 `com.freshlink.common.tracing`(`OutboxTracing`, `MicrometerOutboxTracing`). Micrometer Tracing이 클래스 경로에 있을 때만 켜진다.

## 4. 쓰는 서비스가 할 일

- 의존성 `spring-boot-starter-zipkin` (관측성 작업 때 모든 서비스에 들어갔다)
- `application.yml`에 `spring.cloud.aws.sqs.observation-enabled: true`
- **Flyway 파일은 새로 만들지 않는다.** `trace_parent` 칸은 v0.2.0 표에 이미 있다.

## 5. 배포 순서와 주의할 점

순서 상관없다. v0.2.0으로 적은 행(NULL)도 그대로 보내지고, 받는 쪽이 아직 옛 버전이어도 메시지 속성을 무시할 뿐이다.
