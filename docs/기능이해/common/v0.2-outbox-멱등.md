# common v0.2.0: Outbox 발행기와 멱등 처리

> 담당: 김진아 · 갱신: 2026-10-30 · 상태: 현재 · 태그: v0.2.0 (2026-10-17)

## 1. 한 줄 요약

DB 변경과 쪽지 보내기를 한 묶음으로 만들고(Outbox), 같은 쪽지가 두 번 와도 한 번만 반영하게(멱등) 했다.

## 2. 왜 필요했나

order가 주문을 저장하고 SQS로 RESERVE를 보낼 때, 저장은 됐는데 보내기 전에 파드가 죽으면 쪽지가 사라진다. 반대로 보낸 뒤 저장이 롤백되면 없는 주문의 재고가 잡힌다. 그리고 SQS는 같은 쪽지를 두 번 보낼 수 있어서 재고가 두 번 빠질 수도 있다.

- **Outbox**: 쪽지를 같은 트랜잭션으로 `outbox` 표에 적어 두고, 따로 도는 발행기가 꺼내 보낸다. 저장과 쪽지가 같이 성공하거나 같이 실패한다.
- **멱등**: 받는 쪽이 처리한 `messageId`를 `processed_message` 표에 적어 두고, 이미 있으면 건너뛴다.

둘이 짝이 되어 "정확히 한 번 반영"이 된다.

## 3. 바뀐 것

| 클래스 | 하는 일 |
| --- | --- |
| `OutboxWriter.save(queue, message)` | 쪽지를 같은 트랜잭션으로 `outbox`에 적는다. 트랜잭션 밖이면 예외 |
| `OutboxPublisher` | 1초마다 안 보낸 행을 `id` 순으로 최대 100개 보낸다. FIFO 그룹 = storeId. ShedLock으로 한 파드만 보낸다. 실패하면 그 회차를 멈춰 점포 안 순서를 지킨다 |
| `ProcessedMessages.markIfNew(id)` | 처음이면 기록하고 `true`, 이미 있으면 `false`. `INSERT IGNORE`라 중복이어도 트랜잭션이 깨지지 않는다 |
| `MessagingAutoConfiguration` | `freshlink.messaging.enabled=true`일 때만 위 빈을 만든다. `LockProvider`가 없으면 앱이 뜨지 않는다 |

Spring JDBC, Spring Cloud AWS(SQS), ShedLock은 `compileOnly`라 쓰지 않는 서비스(member, logistics-simulator)에는 끌려가지 않는다.

## 4. 쓰는 서비스가 할 일 (inventory, order)

1. 의존성: starter-jdbc, spring-cloud-aws-starter-sqs, shedlock-spring, shedlock-provider-jdbc-template
2. Flyway로 표 3개: `outbox`, `processed_message`, `shedlock` (DDL은 common README 4-2)
3. `LockProvider` 빈 하나
4. `application.yml`에 `freshlink.messaging.enabled: true`
5. 보낼 때는 `outboxWriter.save`, 받을 때는 `@Transactional` 메서드 첫 줄에서 `markIfNew`
6. IRSA 역할에 보낼 큐의 `sqs:SendMessage` 권한 (infra에서 맞춤)

## 5. 배포 순서와 주의할 점

- `outbox` 표에는 처음부터 `trace_parent` 칸이 있다. v0.3.0이 이 칸을 채운다.
- 처리 중 예외가 나면 처리 기록도 같이 롤백되고, SQS가 다시 보낸다. 계속 실패하면 DLQ로 간다.
