# common v0.5.0: 결제 전 취소와 반품 쪽지

> 담당: 김진아 · 갱신: 2026-10-30 · 상태: 현재 · 태그: v0.5.0 (2026-10-30)

## 1. 한 줄 요약

RELEASE 사유에 `CANCELED`(결제 전 고객 취소, A7)를, 새 쪽지 `RETURN`(환불 뒤 판매 재고 되돌리기, A10)을 더했다.

## 2. 왜 필요했나

2차 범위에서 고객이 결제 전에 주문을 취소하고(A7), 결제한 주문을 환불받을 수 있게(A9) 됐다.

- 결제 전 취소는 잡아 둔 재고를 푸는 것이라 기존 RELEASE를 쓰면 되지만, 사유를 구분해야 해서 `CANCELED`를 더했다.
- 환불은 이미 판매로 확정된 재고를 되돌리는 것이라 RELEASE와 다르다. 그래서 새 쪽지 RETURN을 만들었다.

## 3. 바뀐 것

| 무엇 | 내용 |
| --- | --- |
| `ReleaseReason` | `PAYMENT_FAILED`, `EXPIRED`에 `CANCELED` 추가 |
| `ReturnMessage` (type `RETURN`) | order → `inventory-commands.fifo`. 필드는 `orderId`, `storeId`뿐. `ReturnMessage.of(orderId, storeId)` |

RETURN에 lot이나 수량을 넣지 않은 이유: inventory가 그 주문의 판매 기록(SALE, refId = orderId)으로 원래 lot과 수량을 찾는다. 같은 주문의 RETURN이 messageId가 달라도 **주문당 한 번만** 되돌린다.

## 4. 쓰는 서비스가 할 일

- **inventory (이태우)**: RETURN 처리(판매 기록으로 lot 찾아 복원, 주문당 한 번), RELEASE의 `CANCELED` 처리
- **order (김경우)**: 결제 전 취소 때 `RELEASE(CANCELED)`, 환불 뒤 `RETURN` 보내기

## 5. 배포 순서와 주의할 점

**inventory를 v0.5.0으로 먼저 배포한 뒤** order가 보내기 시작한다. 옛 버전은 `RETURN` 타입과 `CANCELED` 값을 읽지 못해서 처리가 실패하고, 쪽지가 DLQ로 간다.
