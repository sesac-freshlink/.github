### Route 53 도메인 사서 연결
- [ ] Route 53 → **Registered domains**에서 도메인을 산다(`.com` 연 약 15달러, 예산에 반영). 사면 호스팅 영역(월 0.5달러)이 자동으로 생긴다.
- [ ] 주소를 정한다. 예: prod `freshlink.<도메인>`, dev `dev.<도메인>`.
- [ ] infra `envs/<env>/persistent`에 `data "aws_route53_zone"`으로 호스팅 영역을 읽고, CloudFront 배포를 가리키는 A·AAAA **별칭(alias)** 레코드를 만든다.
- [ ] 도메인을 바꾸면 따라 바꿔야 하는 곳: Cognito 콜백·로그아웃 URL(구글 로그인·BFF를 하면), 토스 결제 성공·실패 리디렉트 URL, frontend 배포 워크플로가 출력하는 주소, README·팀원 가이드의 접속 주소.

### CloudFront ACM 인증서
- [ ] CloudFront 인증서는 **`us-east-1`에서만** 만들 수 있다. infra에 `provider "aws" { alias = "us_east_1" region = "us-east-1" }`를 두고 `aws_acm_certificate`(DNS 검증)를 만든다. dev·prod 주소를 둘 다 넣거나 `*.<도메인>` 와일드카드 하나로 한다.
- [ ] 검증 레코드를 Route 53에 `aws_route53_record`로 넣고 `aws_acm_certificate_validation`으로 발급을 기다린다. 공인 인증서라 비용은 없다.
- [ ] `modules/frontend/main.tf`의 `viewer_certificate { cloudfront_default_certificate = true }`를 `acm_certificate_arn`, `ssl_support_method = "sni-only"`, `minimum_protocol_version = "TLSv1.2_2021"`로 바꾸고, `aliases`에 도메인을 넣는다.
- [ ] 바꾼 뒤 `https://<도메인>`으로 접속, 자물쇠 표시, 로그인·결제까지 되는지 dev에서 먼저 확인한다.

### CloudFront CSP 설정
- [ ] `modules/frontend/main.tf`에 `aws_cloudfront_response_headers_policy`를 만들어 기본 동작(S3 화면)에 붙인다. 같은 정책에 HSTS, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`도 넣는다.
- [ ] CSP는 우리가 실제로 부르는 곳만 허용한다. 출발점:
  `default-src 'self'; script-src 'self' https://js.tosspayments.com; connect-src 'self' https://cognito-idp.ap-northeast-2.amazonaws.com https://*.tosspayments.com; frame-src https://*.tosspayments.com; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'`
  (Cognito 주소는 지금처럼 Amplify가 브라우저에서 Cognito를 직접 부를 때만 필요하다. BFF로 바꾸면 뺀다. 지도 API·S3 이미지를 붙이면 그 주소를 더한다.)
- [ ] 처음에는 `Content-Security-Policy-Report-Only`로 dev에 걸어 두고, 브라우저 콘솔에 막힌 주소가 없는지(토스 결제 창, 로그인) 확인한 뒤 실제 `Content-Security-Policy`로 바꾼다.

## BFF로 바꿀 때 할 일

지금은 브라우저의 Amplify가 Cognito에 직접 로그인하고, 토큰(ID·리프레시)을 **localStorage**에 둔다. 프론트는 ID 토큰을 `Authorization: Bearer`로 붙이고, gateway가 JWKS로 검증한다. BFF로 바꾸면 **로그인·토큰 갱신을 gateway가 대신 하고, 토큰은 브라우저 JS가 읽을 수 없는 HttpOnly 쿠키에만 둔다.** **프론트에서 Amplify(`aws-amplify`)는 완전히 빠진다.** 새 서비스를 만들지 않고 gateway를 BFF로 쓴다(CloudFront `/api/*`가 이미 gateway로 가서 같은 주소라 쿠키가 그대로 붙는다).

바뀌는 흐름
1. 화면 → `POST /api/auth/login`(이메일·비밀번호) → gateway가 Cognito `AdminInitiateAuth` 호출 → 응답의 ID·리프레시 토큰을 `Set-Cookie`로 내려 준다. 응답 본문에는 사용자 정보(userId, role, storeId, email)만 준다.
2. 이후 API 요청은 쿠키가 자동으로 붙는다. gateway가 쿠키의 ID 토큰을 꺼내 지금과 같은 방법(JWKS, iss·aud·token_use)으로 검증하고, `UserHeaderFilter`가 지금처럼 사용자 헤더를 만든다. **뒤쪽 서비스(member·inventory·order)는 바뀌지 않는다.**
3. ID 토큰이 만료되어 401이 나면 화면이 `POST /api/auth/refresh`를 한 번 부르고, gateway가 리프레시 쿠키로 Cognito에서 새 ID 토큰을 받아 쿠키를 바꾼다. 그것도 실패하면 "다시 로그인해 주세요".
4. 로그아웃은 `POST /api/auth/logout` → gateway가 Cognito `RevokeToken`으로 리프레시 토큰을 끊고 쿠키를 지운다.

### gateway (김진아)
- [ ] `build.gradle`에 AWS SDK `software.amazon.awssdk:cognitoidentityprovider`와 `runtimeOnly software.amazon.awssdk:sts`(IRSA로 자격 증명을 받기 위해)를 추가한다.
- [ ] `AuthController`(`/auth/**`, 외부 주소는 `/api/auth/**`)를 새로 만든다. gateway 라우트로 넘기지 않고 gateway가 직접 처리한다.
  - `POST /auth/login`: `AdminInitiateAuth`(흐름 `ADMIN_USER_PASSWORD_AUTH`, `SECRET_HASH` 포함). 비밀번호가 틀리면 401과 공통 오류 형식.
  - `POST /auth/signup`, `POST /auth/confirm`: Cognito `SignUp`, `ConfirmSignUp`을 서버에서 부른다. **역할은 지금처럼 `ClientMetadata.role`로 넘겨야** 가입 후 Lambda가 그룹에 넣는다.
  - `POST /auth/refresh`: `AdminInitiateAuth`(흐름 `REFRESH_TOKEN_AUTH`). 리프레시 토큰은 쿠키에서 읽는다. `SECRET_HASH`에는 사용자 `sub`가 필요하니 로그인 때 받은 `sub`도 쿠키나 ID 토큰에서 읽는다.
  - `POST /auth/logout`: `RevokeToken` 후 쿠키 삭제(`Max-Age=0`).
  - `GET /auth/me`: 쿠키의 ID 토큰을 검증해 사용자 정보를 준다. 새로 고침 뒤 로그인 상태 복원에 쓴다.
- [ ] 쿠키 규칙: ID 토큰 `fl_id`(`Path=/api`, 만료 = ID 토큰 만료), 리프레시 `fl_refresh`(`Path=/api/auth`, 만료 = 리프레시 기간). 둘 다 `HttpOnly; Secure; SameSite=Strict`.
- [ ] `SecurityConfig`: `BearerTokenResolver`를 바꿔 `Authorization` 헤더가 없으면 `fl_id` 쿠키에서 토큰을 읽게 한다. `/api/auth/login·signup·confirm·refresh`는 공개(`permitAll`)로 둔다.
- [ ] CSRF: 쿠키로 인증하면 CSRF를 다시 생각해야 한다. `SameSite=Strict`에 더해, 상태를 바꾸는 요청(POST·PUT·PATCH·DELETE)은 사용자 지정 헤더(예: `X-Requested-With: freshlink`)가 없으면 403으로 막는다. 다른 사이트의 폼 전송은 이 헤더를 붙일 수 없다.
- [ ] 설정 추가: `freshlink.cognito.user-pool-id`, `client-id`(새 BFF 클라이언트), `client-secret`(환경 변수 `COGNITO_CLIENT_SECRET`, 파일에 쓰지 않는다).
- [ ] 테스트: 로그인 성공·실패, 쿠키 속성, 쿠키로 보호 경로 통과, 리프레시 성공·실패, 로그아웃 후 쿠키 삭제, 헤더 없는 POST가 403. Cognito는 SDK 클라이언트를 가짜로 바꿔 테스트한다(지금 가짜 JWKS 테스트와 같은 방식).
- [ ] `docs/기술스택과 선택이유.md` 3-7을 "BFF로 바꿈"과 이유로 고친다. gateway README의 JWT 규칙에 쿠키 규칙을 더한다.

### 인프라 (김진아)
- [ ] **Cognito 앱 클라이언트 추가** (`modules/cognito/main.tf`): 지금 `web` 클라이언트는 시크릿 없는 브라우저용이다. 서버용 `bff` 클라이언트를 새로 만든다. `generate_secret = true`, `explicit_auth_flows = ["ALLOW_ADMIN_USER_PASSWORD_AUTH", "ALLOW_REFRESH_TOKEN_AUTH"]`, `enable_token_revocation = true`, 토큰 기간·`read_attributes`(`custom:storeId` 포함)는 `web`과 같게. 바꾸는 동안 `web` 클라이언트는 남겨 두고, 프론트가 다 옮긴 뒤 지운다.
- [ ] **클라이언트 시크릿 보관**: Terraform이 시크릿을 Secrets Manager(`freshlink-<env>/gateway/cognito`)에 넣는다. 출력(output)에 시크릿을 내보내지 않는다.
- [ ] **gateway IRSA 새로 만들기** (`envs/<env>/cluster/main.tf`): 지금 gateway는 AWS를 안 불러서 IRSA가 없다. `modules/irsa`로 gateway 서비스 계정용 Role을 만들고 `cognito-idp:AdminInitiateAuth`를 해당 사용자 풀 ARN에만 허용한다(`SignUp`·`ConfirmSignUp`·`RevokeToken`은 IAM이 필요 없는 공개 API라 시크릿만 있으면 된다).
- [ ] **ArgoCD 루트 값 전달** (`charts/argocd-root` 값): gateway에 IRSA Role ARN, `COGNITO_USER_POOL_ID`, 새 `COGNITO_CLIENT_ID`(bff)를 넘긴다. 토큰 `aud`가 bff 클라이언트 ID가 되므로 gateway 검증 값도 같이 바뀐다.
- [ ] **gitops 차트** (`charts/spring-service`): 지금 ExternalSecret은 DB 비밀(`db.secretName`)만 받는다. 일반 비밀을 환경 변수로 넣는 값(예: `extraSecrets`)을 추가해 gateway가 `COGNITO_CLIENT_SECRET`을 받게 하고, `envs/dev·prod/gateway/values.yaml`에 서비스 계정 IRSA 주석과 비밀 이름을 넣는다.
- [ ] **CloudFront** (`modules/frontend/main.tf`): `/api/*` 오리진 요청 정책이 이미 AllViewerExceptHostHeader라 쿠키는 gateway까지 넘어간다. 캐시 정책 `api`는 지금 `Authorization`만 넣으므로, 쿠키 이름(`fl_id`, `fl_refresh`)을 캐시 키에 넣거나 그대로 두어도 되는지(기본 TTL 0이라 캐시는 안 됨) dev에서 `Set-Cookie`가 브라우저까지 오는지 확인한다.
- [ ] **post-confirmation Lambda**: 가입을 서버에서 해도 트리거 출처(`PostConfirmation_ConfirmSignUp`)와 `clientMetadata`가 같은지 dev에서 확인한다.
- [ ] **프론트 배포 워크플로**(frontend `frontend-deploy.yml`): Amplify를 빼면 `VITE_COGNITO_USER_POOL_ID`, `VITE_COGNITO_CLIENT_ID` 주입을 지운다.
- [ ] dev에 먼저 적용하고 확인한 뒤 prod에 같은 순서로 적용한다. 구글 로그인을 같이 하면 `bff` 클라이언트에 Hosted UI 도메인, `allowed_oauth_flows = ["code"]`, 콜백 `https://<CloudFront>/api/auth/callback`을 넣고 gateway에 `GET /auth/google`(리디렉트)·`GET /auth/callback`(코드 → 토큰 교환 후 쿠키)을 더한다.
