## BFF로 바꿀 때 할 일

멘토링에서 토큰을 브라우저(`localStorage`)가 아니라 서버에 두는 BFF 이야기가 나왔다. 지금 구조와 왜 Amplify를 골랐는지는 `docs/기술스택과 선택이유.md` 3-7에 있다. 아래는 **BFF로 바꾸기로 하면** 무엇을 어디에 추가하는지다. 바꾸기로 하면 위의 "리프레시 토큰 설정"(김진아)과 "리프레시 토큰 재발급 화면"(김경우)은 이 절로 대신한다.

### 지금 구조 (바꾸기 전)

- 브라우저가 Amplify Auth(`aws-amplify`)로 Cognito에 직접 로그인(SRP)하고, 토큰을 `localStorage`에 둔다(frontend `src/shared/auth/cognitoClient.ts`).
- axios가 요청마다 `Authorization: Bearer <ID 토큰>`을 붙인다(frontend `src/shared/api/client.ts`).
- CloudFront가 `/api/*`를 gateway ALB로 넘긴다(infra `modules/frontend/main.tf`). 화면과 API가 같은 주소라 CORS가 없다.
- gateway(Spring Cloud Gateway **WebMVC**)는 Resource Server로 JWT만 검증하고, `UserHeaderFilter`가 `X-User-Id`·`X-User-Role`·`X-Store-Id`를 채운다. 세션이 없는 무상태 구조다.
- Cognito 앱 클라이언트는 브라우저용 공개 클라이언트 1개(`web`, 시크릿 없음, SRP)이고, Cognito 도메인(로그인 화면 주소)은 없다.

### 바꾼 뒤 구조 (안)

**새 서버를 따로 만들지 않고 gateway가 BFF 역할을 같이 한다.** 모든 `/api/*` 요청이 이미 gateway를 지나고, 화면과 같은 주소(CloudFront)라 쿠키를 그대로 쓸 수 있어서 가장 적게 바꾸는 방법이다.

1. 화면에서 "로그인"을 누르면 브라우저가 `/api/auth/login`으로 이동하고, gateway가 Cognito 로그인 화면(Managed Login, 예전 Hosted UI)으로 보낸다.
2. 로그인 후 Cognito가 `/api/login/oauth2/code/cognito`로 돌려보낸다. gateway가 클라이언트 시크릿으로 코드를 토큰으로 바꾸고, **토큰은 세션 저장소(Redis)에 둔다.**
3. 브라우저에는 `HttpOnly`·`Secure`·`SameSite=Lax` 세션 쿠키만 간다. 자바스크립트로 읽을 수 없다.
4. API 요청 때 gateway가 세션에서 ID 토큰을 꺼내 지금처럼 검증하고 헤더를 채운다. 뒤 서비스(member·inventory·order)는 **바뀌는 것이 없다.**
5. 토큰이 만료되면 gateway가 리프레시 토큰으로 서버에서 갱신한다.

### 먼저 정할 것 (같이)

- [ ] **로그인 화면:** Cognito Managed Login(가입·이메일 인증·비밀번호 찾기 화면을 Cognito가 준다)으로 바꿀지, 직접 만든 가입·로그인 화면(C-01, C-02)을 유지할지 정한다. 직접 만든 화면을 유지하면 비밀번호가 gateway를 거쳐야 해서(`USER_PASSWORD_AUTH`) 보안상 이득이 줄어든다. **Managed Login을 권장**하고 로고·색만 맞춘다.
- [ ] **세션 저장소:** 클러스터 안 Redis 파드(비용 0, 주말 클러스터 삭제 때 세션이 사라져 월요일에 다시 로그인) 또는 ElastiCache(월 약 12 USD 안팎·추정, dev·prod 따로면 두 배). MVP는 **클러스터 안 Redis 파드**를 권장한다. 선착순 대기열을 Redis로 하기로 하면 같은 Redis를 같이 쓸지도 정한다.
- [ ] **기존 Bearer 방식을 언제 끌지:** 전환 기간에는 gateway가 쿠키와 Bearer를 둘 다 받게 하고, 프론트가 다 바뀌면 Bearer를 끈다. 시드 스크립트와 curl 테스트가 Bearer를 쓰므로 dev에서는 계속 열어 둘지 정한다.

### 김진아: infra 레포

- [ ] **Cognito 도메인:** `modules/cognito`에 `aws_cognito_user_pool_domain`(접두사 예: `freshlink-dev`, `freshlink-prod`)을 추가한다. 유지 묶음(`envs/<env>/persistent`)이라 주말 삭제와 상관없다. Managed Login을 쓰면 `aws_cognito_managed_login_branding`으로 로고·색을 넣는다.
- [ ] **BFF용 앱 클라이언트 추가:** 기존 `web` 클라이언트는 전환 기간 동안 두고 `aws_cognito_user_pool_client.bff`를 새로 만든다.
  - `generate_secret = true` (서버 전용 비밀 클라이언트)
  - `allowed_oauth_flows_user_pool_client = true`, `allowed_oauth_flows = ["code"]`, `allowed_oauth_scopes = ["openid", "email", "profile"]`, `supported_identity_providers = ["COGNITO"]` (구글 로그인을 하면 `"Google"` 추가)
  - `callback_urls`: `https://<CloudFront 주소>/api/login/oauth2/code/cognito`. dev는 로컬 개발용 `http://localhost:5173/api/login/oauth2/code/cognito`도 넣는다.
  - `logout_urls`: `https://<CloudFront 주소>/` (dev는 localhost도)
  - 토큰 유효기간과 `read_attributes`(`custom:storeId` 포함)는 기존 `web` 클라이언트와 같게 둔다.
  - CloudFront 주소는 frontend 모듈 출력값을 cognito 모듈 입력으로 넘긴다(둘 다 persistent 루트라 같은 곳에서 연결할 수 있다).
- [ ] **클라이언트 시크릿 보관:** 시크릿을 Secrets Manager(예: `freshlink/<env>/gateway/cognito-client-secret`)에 Terraform으로 넣고, gateway IRSA 역할에는 이 시크릿 읽기 권한만 준다. Terraform state에 시크릿이 남는 점은 state 버킷 암호화로 받아들인다.
- [ ] **CloudFront 확인:**
  - `/api/*` 동작은 이미 쿠키·헤더를 모두 넘긴다(`origin_request_all_viewer_host`). `/api/auth/*`와 `/api/login/*` 응답이 캐시되지 않는지(`aws_cloudfront_cache_policy.api`의 TTL 0) 확인한다.
  - 응답 헤더 정책으로 CSP를 넣는다(3-7 "다음 단계"). Amplify를 빼면 브라우저가 Cognito를 직접 부르지 않으므로 `connect-src 'self'`로 줄일 수 있다.
- [ ] **세션 저장소(ElastiCache로 정하면):** `modules/`에 `elasticache` 모듈을 새로 만든다. `cache.t4g.micro` 1대, 프라이빗 서브넷의 서브넷 그룹, EKS 노드 보안 그룹에서 6379만 허용하는 보안 그룹, 전송 중 암호화(TLS)와 AUTH 토큰(Secrets Manager). persistent 루트(24시간 요금)에 둘지 cluster 루트(주말에 같이 삭제)에 둘지 정하고, dev·prod 합계 비용을 다시 계산한다.
- [ ] **NAT:** gateway가 Cognito 토큰 주소(`https://<도메인>.auth.ap-northeast-2.amazoncognito.com/oauth2/token`)를 부르므로 지금처럼 NAT로 나간다. 추가 작업은 없지만, NAT를 끄는 시간에는 로그인도 안 된다는 점을 문서에 적는다.

### 김진아: gitops 레포

- [ ] **Redis(클러스터 안으로 정하면):** `platform/` 아래에 Redis 1개(Deployment + Service, 메모리 128~256 MiB, 비밀번호는 ExternalSecret)를 ArgoCD Application으로 추가한다. 노드 2대 CPU 요청이 이미 높으므로(3-5) 요청량을 작게 잡는다. 데이터는 휘발성으로 두고 PVC는 만들지 않는다.
- [ ] **gateway values(`envs/{dev,prod}/gateway/values.yaml`):** ExternalSecret으로 `COGNITO_BFF_CLIENT_SECRET`과 Redis 비밀번호를 넣고, 환경 변수 `COGNITO_BFF_CLIENT_ID`, `COGNITO_DOMAIN`, `SPRING_DATA_REDIS_HOST`, `PUBLIC_BASE_URL`(CloudFront 주소)을 추가한다. dev·prod 키를 똑같이 맞춘다.
- [ ] gateway 파드가 2개 이상이어도 세션이 Redis에 있으므로 고정 세션(sticky)은 필요 없다. ALB 설정은 그대로 둔다.

### 김진아: gateway 레포

- [ ] **의존성 추가(`build.gradle`):** `spring-boot-starter-oauth2-client`, `spring-session-data-redis`, `spring-boot-starter-data-redis`. 기존 `oauth2-resource-server`는 전환 기간 동안 둔다.
- [ ] **OAuth2 클라이언트 설정(`application.yml`):** `spring.security.oauth2.client.registration.cognito`(client-id·secret, `authorization-grant-type: authorization_code`, scope `openid,email,profile`, `redirect-uri: {baseUrl}/api/login/oauth2/code/cognito`)와 `provider.cognito.issuer-uri`(지금 Resource Server와 같은 값).
- [ ] **경로를 `/api` 아래로:** CloudFront는 `/api/*`만 gateway로 보내므로 로그인 시작 주소를 `/api/oauth2/authorization/cognito`로, 콜백을 `/api/login/oauth2/code/cognito`로 바꾼다(`authorizationEndpoint.baseUri`, `redirectionEndpoint.baseUri`). 프론트가 부를 짧은 주소도 만든다.
  - `GET /api/auth/login`: `/api/oauth2/authorization/cognito`로 이동
  - `GET /api/auth/me`: 세션의 ID 토큰에서 `sub`, 이메일, 그룹, `storeId`만 JSON으로 준다(토큰 자체는 주지 않는다). 로그인 안 했으면 401
  - `POST /api/auth/logout`: 세션을 지우고 Cognito `/logout?client_id=…&logout_uri=…`로 보내 Cognito 쪽 로그인 상태도 끊는다. 리프레시 토큰은 `/oauth2/revoke`로 무효화한다.
- [ ] **세션 쿠키:** 이름 예 `FLSESSION`, `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/api`. 세션 만료는 리프레시 토큰 기간(1일)에 맞춘다.
- [ ] **`SecurityConfig` 바꾸기:**
  - `oauth2Login()`을 켜고, 로그인 성공 뒤 프론트 첫 화면(`/`)으로 보낸다.
  - API 요청은 세션이 있으면 세션의 ID 토큰으로, 없으면(전환 기간) 기존 Bearer로 인증한다. 둘 다 없으면 지금처럼 401 JSON(`ErrorResponseWriter`)을 준다. **API 요청에는 로그인 화면으로 가는 302를 보내지 않는다.**
  - `CognitoJwtValidators`(`token_use=id`, `aud` 확인)를 세션에서 꺼낸 ID 토큰에도 똑같이 쓴다. 전환 기간에는 `aud`로 `web`·`bff` 두 클라이언트 ID를 모두 허용한다.
- [ ] **CSRF:** 쿠키를 쓰므로 CSRF 방어를 켠다. `CookieCsrfTokenRepository.withHttpOnlyFalse()`(쿠키 `XSRF-TOKEN`, 헤더 `X-XSRF-TOKEN`)로 POST·PUT·PATCH·DELETE에서 확인한다. 외부에서 들어오는 콜백 요청이 있으면 그 경로만 뺀다.
- [ ] **`UserHeaderFilter`:** 지금처럼 들어온 `X-User-*`·`X-Store-Id`를 지우고 인증 정보(세션의 ID 토큰 또는 Bearer)로 다시 채운다. 뒤 서비스로 `Cookie` 헤더(세션 쿠키)는 넘기지 않는다.
- [ ] **토큰 갱신:** `OAuth2AuthorizedClientManager`에 refresh token 제공자를 넣어 만료 전에 서버에서 갱신한다. 새로 받은 ID 토큰으로 세션의 사용자 정보도 바꿔야 한다(Spring Security의 OIDC ID 토큰 갱신 처리 확인). 갱신이 실패하면(리프레시 만료) 세션을 지우고 401을 준다.
- [ ] **테스트:** 로그인 콜백 후 세션 생성, 세션으로 API를 부를 때 헤더 주입, CSRF 토큰 없는 POST 거절, 위조 `X-User-Id` 제거, 로그아웃 후 401을 테스트로 남긴다.
- [ ] **관측성:** 로그인 성공·실패와 토큰 갱신 실패 수를 지표(Micrometer)로 남긴다. 로그에 토큰·쿠키 값이 찍히지 않게 한다.
