## 2. 화살표(번호 = 배지)

1. 사용자 → CloudFront (HTTPS, 한 주소)
2. CloudFront → S3: `/` 화면 (OAC)
3. CloudFront → IGW → ALB: `/api/*`
4. ALB → gateway 파드 (target type `ip`, 두 AZ)
5. gateway → member / inventory / order: 노드 안에서 경로별로 갈라지는 화살표 + 빨간 설명 상자(JWKS 검증·OWNER 확인·헤더 재작성). gateway → Cognito JWKS 점선과 연결
6. 서비스 파드 ↔ RDS MySQL (서비스별 스키마)
7. simulator·order → `inventory-commands.fifo` → inventory → `inventory-results` → order, 실패 3번 → DLQ (IRSA로 권한 분리)
8. order → NAT → IGW → 토스페이먼츠 (결제 승인)
9. GitHub Actions → ECR (OIDC로 IAM Role, 이미지 푸시)
10. GitHub Actions → `gitops` 레포 (이미지 태그 커밋)
11. ArgoCD ← `gitops` 레포 (pull, 동기화) / 노드 ← ECR (이미지 pull)
12. GitHub Actions → S3 업로드 + CloudFront 무효화 (프론트 배포)
13. Loki → S3 로그 버킷 (IRSA)
14. EventBridge Scheduler → RDS·SSM용 EC2 중지·시작, 노드 그룹 0↔2
15. 사용자 → Amazon Cognito (가입·로그인, JWT 발급). Region 안·VPC 밖 오른쪽 위에 둔다. gateway는 Cognito 공개 키(JWKS)로 검증 (5번)

16. Secrets Manager → External Secrets Operator (IRSA) → K8s Secret → 앱 파드
17. 개발자 PC → SSM Session Manager → t4g.nano → dev RDS (포트 포워딩 127.0.0.1:3306)

실선 = 사용자 요청 경로, 점선 = 비동기 메시지·배포·관리 경로. 오른쪽 아래 범례 상자에 dev·prod(같은 구조 두 번, 환경마다 따로인 것, 공용인 것).

## 2-1. 다음에 그림을 다시 만들 때 더할 것 (2026-10-28 2차 결정)

2차 구현이 끝나면 아래를 그림에 더한다. 자세한 설명은 [README.md](README.md) 12장.

- 15번을 "사용자 → gateway `/api/auth/**` → Cognito"로 바꾸고 사용자 → Cognito 직접 화살표를 지운다(BFF).
- EKS에 notification-service 파드, SQS 열에 `notification-events`와 DLQ, CloudWatch 경보 → 웹훅.
- app 서브넷 옆에 ElastiCache for Valkey(order만 연결).
- CloudFront 앞에 Route 53, ACM 인증서 표시를 실제 도메인 기준으로.
- ECR 리포 6개.

## 3. 배치

- 가로 1960 × 세로 1300. 왼쪽 열(사용자·GitHub) → AWS 관리형 열 → VPC → SQS 열 → 토스 순으로 왼쪽에서 오른쪽 흐름.
- VPC 안은 예시처럼 AZ 2a를 위, 2c를 아래 줄에 두고, 두 AZ 사이 띠에 IGW·ALB·EKS 클러스터 라벨·SQS 연결선을 둔다.
- 서브넷 열 순서: public → app → db (왼쪽에서 오른쪽).
- 색: 네트워킹 보라, 컴퓨팅·컨테이너 주황, 스토리지 초록, DB 파랑, 앱 통합 분홍, 보안 빨강 (AWS 아이콘 색 체계).
