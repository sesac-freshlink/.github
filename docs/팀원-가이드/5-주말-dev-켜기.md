# 팀원 가이드 5. 주말에 dev 직접 켜고 끄기

작성: 김진아 · 2026-10-23 · 대상: 이태우, 김경우

> **한 줄 요약:** 주말에는 dev가 통째로 꺼져 있다. 켤 때는 **GitHub 버튼 하나(create)** 와 **AWS 콘솔에서 RDS·접속용 서버 켜기 두 번**, 끌 때는 **버튼 하나(destroy)** 와 **콘솔에서 두 번 끄기**다. 다 쓰면 **반드시 끈다.** 켜 둔 채로 두면 월요일 아침까지 하루 약 1만 원씩 나간다.

인프라를 몰라도 이 문서 순서대로 누르기만 하면 된다. 명령은 모두 Windows PowerShell 기준이다.

## 1. 언제 이 문서가 필요한가

평일에는 자동으로 켜지고 꺼진다([가이드 2의 7장](2-인프라-배포.md#7-켜고-끄는-일정)). 주말에는 이렇게 되어 있다.

| 무엇 | 주말 상태 | 주말에 켜는 법 |
| --- | --- | --- |
| dev 클러스터 (gateway·서비스 파드, NAT, 노드 2대) | **없다.** 금요일 21:05에 통째로 지운다 | GitHub Actions `dev-cluster` → `create` |
| RDS (`freshlink-dev-mysql`) | 꺼져 있다 | AWS 콘솔 RDS → 시작 |
| DB 접속용 서버 (`freshlink-dev-ssm-access`) | 꺼져 있다 | AWS 콘솔 EC2 → 인스턴스 시작 |
| dev 화면 (https://dywjl1yyfi1z1.cloudfront.net) | 화면은 열리지만 `/api`는 안 된다 | 클러스터가 켜지면 된다 |

무엇을 할지에 따라 켤 것이 다르다.

| 하고 싶은 것 | 켤 것 |
| --- | --- |
| **내 PC에서 서비스를 띄워 dev DB에 붙기** (IntelliJ 실행) | RDS + 접속용 서버만 (3-2, 3-3). 클러스터는 안 켜도 된다 |
| **dev 화면·API로 확인하기** (배포된 서비스, 화면 연동) | 셋 다 (3-1, 3-2, 3-3) |

클러스터를 켜지 않으면 비용이 훨씬 적다. 내 PC 개발만 할 거면 RDS와 접속용 서버만 켠다.

- 클러스터를 지워도 **DB 데이터, 큐, 이미지, 회원 계정은 남는다.** 켜면 gitops에 적힌 버전 그대로 다시 뜬다.
- 월요일 08:40에는 원래대로 자동으로 켜진다. 일요일에 꺼 두면 된다.

## 2. 처음 한 번: 준비

### 2-1. GitHub: Run workflow 버튼이 보이는지

1. 브라우저로 https://github.com/sesac-freshlink/infra/actions/workflows/dev-cluster.yml 을 연다(GitHub 로그인 상태).
2. 오른쪽 위에 회색 **Run workflow** 버튼이 보이면 준비 끝이다.
3. 버튼이 없으면 infra 레포 쓰기 권한이 없는 것이다. 김진아에게 "infra 레포 Write 권한 주세요"라고 말한다.

### 2-2. AWS 콘솔: sesac 계정으로 로그인되는지

RDS·서버 켜기는 평소 쓰는 `freshlink-<이름>` 계정(`freshlink-dev` 프로필)으로는 **안 된다.** 그 계정은 일부러 dev 큐·비밀·DB 접속만 되게 막아 두었다. 켜고 끄기는 새싹에서 받은 **sesac 계정**으로 콘솔에 들어가서 한다.

| 사람 | 콘솔 사용자 이름 |
| --- | --- |
| 김경우 | `sesac-c1` |
| 이태우 | `sesac-c4` |

1. 새싹에서 받은 콘솔 로그인 주소로 들어가 위 사용자 이름과 비밀번호로 로그인한다.
2. 오른쪽 위 지역이 **아시아 태평양(서울) ap-northeast-2**인지 본다. 아니면 눌러서 서울로 바꾼다.
3. 위쪽 검색창에 `RDS`를 쳐서 들어가 **데이터베이스** 목록에 `freshlink-dev-mysql`이 보이면 준비 끝이다.

> sesac 계정은 dev·prod를 가리지 않고 거의 모든 것을 할 수 있다. **이 문서에 적힌 것 말고는 누르지 않는다.** 특히 이름에 `prod`가 들어간 것은 건드리지 않는다.

### 2-3. 팀 채팅에 알리기

주말에 누가 켜고 누가 끄는지 헷갈리지 않게, 켤 때와 끌 때 팀 채팅에 한 줄 남긴다.

- 켤 때: "dev 켭니다 (클러스터 O / DB만)"
- 끌 때: "dev 껐습니다"
- 다른 사람이 이미 켰으면 다시 켜지 않고 같이 쓴다. **마지막에 쓰는 사람이 끈다.**

## 3. 켜기 (약 25분)

세 가지를 **한꺼번에 눌러 두고** 기다리면 된다. 순서는 상관없다.

### 3-1. 클러스터 켜기 (GitHub, 15~20분) — dev 화면·API가 필요할 때만

1. https://github.com/sesac-freshlink/infra/actions/workflows/dev-cluster.yml 을 연다.
2. 오른쪽 **Run workflow** 를 누른다. 작은 창이 열린다.
3. 아래처럼 고른다.

   | 칸 | 넣을 값 |
   | --- | --- |
   | Use workflow from | `Branch: main` (그대로) |
   | action | **`create`** |
   | env | **`dev`** (그대로. **절대 prod를 고르지 않는다**) |
   | lock_id | 비워 둔다 |

4. 초록 **Run workflow** 를 누른다.
5. 몇 초 뒤 목록 맨 위에 **`dev create`** 줄이 노란 동그라미(도는 중)로 생긴다. 15~20분 뒤 **초록 체크**가 되면 끝이다.

### 3-2. RDS 켜기 (AWS 콘솔, 5~10분)

1. sesac 계정으로 콘솔에 로그인하고, 지역이 **서울**인지 본다.
2. 검색창에 `RDS` → 왼쪽 **데이터베이스**.
3. `freshlink-dev-mysql` 왼쪽 동그라미를 누른다.
4. 오른쪽 위 **작업** → **시작**. 확인 창이 나오면 **시작**.
5. 상태가 `시작 중` → `사용 가능`(Available)이 되면 끝이다. 5~10분 걸린다. 새로 고침 버튼(동그란 화살표)으로 다시 본다.

### 3-3. DB 접속용 서버 켜기 (AWS 콘솔, 1~2분)

1. 검색창에 `EC2` → 왼쪽 **인스턴스**.
2. 목록에서 이름이 `freshlink-dev-ssm-access` 인 줄을 체크한다. (이름이 `freshlink-dev-nodes` 같은 다른 서버는 건드리지 않는다.)
3. 오른쪽 위 **인스턴스 상태** → **인스턴스 시작**.
4. 인스턴스 상태가 `실행 중`(Running)이 되면 끝이다.

## 4. 켜졌는지 확인

### 4-1. dev API (클러스터를 켰을 때)

PowerShell을 열고 친다.

```powershell
try { Invoke-RestMethod "https://dywjl1yyfi1z1.cloudfront.net/api/members/me" } catch { $_.Exception.Response.StatusCode.value__ }
```

- **`401`이 나오면 성공이다.** 토큰 없이 보냈는데 gateway까지 닿았다는 뜻이다.
- `502`·`503`·`504`면 아직 서비스 파드가 뜨는 중이다. 3~5분 뒤 다시 친다. 15분이 지나도 그대로면 7장을 본다.
- 그다음 브라우저로 https://dywjl1yyfi1z1.cloudfront.net 을 열어 시드 계정으로 로그인해 본다([가이드 3의 2장](3-프론트-연동.md#2-시드-계정으로-로그인하기)).

> 서비스가 DB를 쓰므로, RDS가 `사용 가능`이 되기 전에 파드가 먼저 뜨면 잠깐 재시작을 반복할 수 있다. RDS가 켜지고 몇 분 지나면 저절로 정상이 된다.

### 4-2. DB 포트 포워딩 (내 PC에서 개발할 때)

평소처럼 [팀원-가이드/0-개발환경-접속.md](0-개발환경-접속.md) 2장대로 포트 포워딩 창을 연다. `Waiting for connections...`가 나오면 성공이다.

- 접속용 서버를 막 켰으면 1~2분 동안 `TargetNotConnected`가 날 수 있다. 2분 뒤 다시 한다.

## 5. 끄기 (약 25분)

다 쓰면 **켠 것을 모두** 끈다. 이것도 세 개를 한꺼번에 눌러 두면 된다.

### 5-1. 클러스터 끄기 (GitHub, 15~25분)

1. https://github.com/sesac-freshlink/infra/actions/workflows/dev-cluster.yml 을 연다.
2. **Run workflow** → action **`destroy`**, env **`dev`**, lock_id 비움 → 초록 **Run workflow**.
3. 목록 맨 위 **`dev destroy`** 가 **초록 체크**가 될 때까지 둔다. **도는 중에 절대 취소(Cancel)하지 않는다**(6장).
4. 초록 체크가 되면 그 줄을 눌러 아래 **요약(Summary)** 의 "남은 리소스" 표가 모두 `없음`인지 본다.

### 5-2. RDS 끄기 (AWS 콘솔)

1. RDS → **데이터베이스** → `freshlink-dev-mysql` 선택.
2. **작업** → **일시적으로 중지**(Stop temporarily). 스냅샷을 만들지 묻는 칸은 **체크하지 않는다**. "7일 후 자동으로 다시 시작된다"는 안내에 체크하고 **일시적으로 중지**.
3. 상태가 `중지 중` → `중지됨`이 되면 끝이다.
   - `시작 중`일 때는 끌 수 없다. `사용 가능`이 된 뒤 끈다. 깜빡해도 **매일 23:00에 자동으로 한 번 더 끈다.**

### 5-3. DB 접속용 서버 끄기 (AWS 콘솔)

1. EC2 → **인스턴스** → `freshlink-dev-ssm-access` 체크.
2. **인스턴스 상태** → **인스턴스 중지**. (**종료(Terminate)** 가 아니다. 종료를 누르면 서버가 지워진다.)
3. `중지됨`이 되면 끝이다.

### 5-4. 끄고 나서

팀 채팅에 "dev 껐습니다"를 남긴다.

## 6. 꼭 지킬 것

| 하지 말 것 | 이유 |
| --- | --- |
| **destroy 도중에 취소(Cancel)** | 지우다 만 상태와 잠금 파일이 남아 다음 create·destroy가 전부 실패한다. 김진아가 손으로 풀어야 한다. 오래 걸려도 끝날 때까지 둔다 (최대 90분이면 저절로 끝난다) |
| **env에 `prod` 고르기** | 실제 서비스 환경이다. prod는 릴리스 날 김진아만 켠다 |
| **평일에 destroy 누르기** | 평일에는 클러스터를 지우지 않는다. 지우면 다음 날 아침 자동으로 다시 만들어지지 않아(월요일만 만든다) 그 주 dev가 멈춘다 |
| **켜 둔 채로 자기** | 클러스터·노드는 밤에 저절로 꺼지지 않는다. 월요일 아침까지 두면 약 2~3만 원이 나간다 |
| EC2에서 **종료(Terminate)**, RDS에서 **삭제** | 되돌릴 수 없다. 이 문서에는 "중지"만 있다 |
| sesac 계정으로 다른 것 바꾸기 | 이 문서에 적힌 버튼만 누른다 |

**밤 23:00 이후에는 dev가 반쯤 꺼진다.** 매일 23:00에 RDS·접속용 서버가, 23:05에 NAT(클러스터의 인터넷 출구)가 자동으로 꺼진다. 그래서 주말에도 **23:00 전에 끝내고 끈다.** (이 자동 끄기는 안전장치일 뿐이고 클러스터·노드는 지워 주지 않는다. 5-1은 꼭 직접 한다.)

**비용 감.** 다 켜면 시간당 약 0.4달러(약 600원)다. 낮 동안 8시간 쓰면 5천 원쯤, DB만 켜면 그보다 훨씬 적다. 팀 지원금 안에서 쓰는 돈이라 쓴 만큼만 켠다.

## 7. 문제가 생기면

| 증상 | 할 일 |
| --- | --- |
| Run workflow 버튼이 없다 | 2-1. 김진아에게 infra Write 권한을 요청한다 |
| `create`가 빨간 X | 한 번만 다시 create를 누른다. 또 빨간 X면 **destroy를 눌러 끝까지 돌리고**, 빨간 X 줄의 실패한 단계 이름과 화면 캡처를 김진아에게 보낸다 |
| `destroy`가 빨간 X | 한 번 더 destroy를 누른다. 또 빨간 X면 그대로 두고 김진아에게 캡처를 보낸다 (create는 누르지 않는다) |
| 로그에 `Error acquiring the state lock` | 다른 작업이 남긴 잠금이다. 아무것도 누르지 말고 김진아에게 그 로그의 `Lock Info` 부분 캡처를 보낸다 |
| 목록에서 내 실행이 `Queued`(대기)로 안 움직인다 | 다른 사람이 누른 create·destroy가 도는 중이다. 한 번에 하나씩만 돈다. 앞의 것이 끝나면 저절로 시작한다 |
| 4-1이 15분 넘게 `502`·`503` | RDS가 `사용 가능`인지 본다. 맞으면 김진아에게 알린다 |
| 콘솔에서 **시작**이 회색이거나 권한 오류 | `freshlink-<이름>` 계정으로 들어가 있는 것이다. 로그아웃하고 sesac 계정으로 다시 들어간다 |
| 콘솔에 `freshlink-dev-mysql`이 안 보인다 | 지역이 서울(ap-northeast-2)인지 본다 |
| 포트 포워딩이 `TargetNotConnected` | 접속용 서버가 `실행 중`인지, 켠 지 2분이 지났는지 본다 |
