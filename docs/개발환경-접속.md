# 개발 환경 접속 가이드

PC에서 서비스를 띄울 때도 AWS dev 환경의 RDS·SQS를 그대로 쓴다. 이 문서 순서대로 하면 서비스 하나를 dev RDS에 붙여 띄울 수 있다. 명령은 모두 Windows PowerShell 기준이다.

| 담당 | 서비스 | DB 비밀 | DB 사용자 / 스키마 | 개인 큐 접두사 |
| --- | --- | --- | --- | --- |
| 이태우 | inventory-service | `freshlink-dev-inventory-db` | `inventory_app` / `inventory` | `dev-taewoo-` |
| 김경우 | member-service | `freshlink-dev-member-db` | `member_app` / `member` | `dev-kyungwoo-` |
| 김경우 | order-service | `freshlink-dev-order-db` | `order_app` / `orders` | `dev-kyungwoo-` |

- dev RDS는 **평일 09:00~21:00에만 켜져 있다**(매일 23:00에 한 번 더 끈다). 이 시간 밖에서는 접속되지 않는다.
- `<인스턴스 ID>`(SSM 접속용 서버, `i-`로 시작)와 `<DB 주소>`(`freshlink-dev-mysql....rds.amazonaws.com`)는 김진아에게 받는다. 이 레포는 공개라 여기에 적지 않는다.

## 1. 처음 한 번: 설치와 로그인

### 1-1. 프로그램 설치

```powershell
winget install --id Amazon.AWSCLI -e --source winget
winget install --id Amazon.SessionManagerPlugin -e --source winget
```

- `--source winget`을 빼면 msstore 인증서 오류(`0x8a15005e`)가 날 수 있다.
- 설치 뒤 PowerShell 창을 **새로 연다**. 열려 있던 창은 새 프로그램을 못 찾는다.
- 확인: `aws --version`, `session-manager-plugin`("...installed successfully"가 나오면 성공)

### 1-2. AWS 로그인 (프로필 `freshlink-dev`)

김진아에게 받은 로그인 주소·사용자 이름(`freshlink-<이름>`)·임시 비밀번호로 콘솔에 로그인해 새 비밀번호로 바꾼다. 그다음 오른쪽 위 이름 → **보안 자격 증명** → **액세스 키 만들기**(사용 사례 "CLI")로 키를 받아 넣는다.

```powershell
aws configure --profile freshlink-dev
#   AWS Access Key ID:     (받은 액세스 키)
#   AWS Secret Access Key: (받은 비밀 키)
#   Default region name:   ap-northeast-2
#   Default output format: json

aws sts get-caller-identity --profile freshlink-dev   # "user/freshlink/freshlink-<이름>"이 나오면 성공
```

- MFA는 강제하지 않는다. 쓰고 싶으면 같은 **보안 자격 증명** 화면에서 MFA 기기를 등록한다(콘솔 로그인에 쓰인다).
- 매번 `--profile`을 붙이기 싫으면 창마다 먼저 `$env:AWS_PROFILE = "freshlink-dev"`를 친다. 아래 명령은 이렇게 했다고 보고 `--profile`을 뺐다.
- 이 계정은 dev 리소스만 쓸 수 있다(이름이 `dev-`인 큐, `freshlink-dev-`인 비밀). prod는 읽기도 안 된다.

## 2. DB 포트 포워딩 (서비스를 띄울 때마다)

창 하나를 열어 아래 한 줄을 치고 **그 창은 닫지 않는다**. 내 PC `127.0.0.1:3306`이 SSM 접속용 서버를 거쳐 dev RDS로 이어진다.

```powershell
aws ssm start-session --profile freshlink-dev --target <인스턴스 ID> --document-name AWS-StartPortForwardingSessionToRemoteHost --parameters "host=<DB 주소>,portNumber=3306,localPortNumber=3306"
```

- `Waiting for connections...`가 나오면 성공이다. 끝낼 때는 Ctrl+C.
- **PC에 MySQL이 깔려 있으면** 3306을 이미 쓰고 있어 RDS가 아니라 내 PC MySQL에 붙는다. `localPortNumber=3307`로 바꾸고, 아래 `DB_URL`도 `3307`로 쓴다. (확인: `Get-NetTCPConnection -LocalPort 3306 -State Listen -ErrorAction SilentlyContinue`에 아무것도 안 나오면 3306을 써도 된다)
- `TargetNotConnected`가 나오면 21:00~09:00(꺼진 시간)인지 확인하고, 시간 안이면 김진아에게 알린다.

## 3. IntelliJ 실행 구성

**Run → Edit Configurations →** 서비스의 Spring Boot 실행 구성 → **Environment variables**에 아래를 넣는다(이태우 예시. 김경우는 위 표대로 바꾼다).

```
SPRING_PROFILES_ACTIVE=dev
AWS_PROFILE=freshlink-dev
AWS_REGION=ap-northeast-2
DB_URL=jdbc:mysql://127.0.0.1:3306/inventory
DB_USERNAME=inventory_app
DB_PASSWORD=<아래 명령으로 복사한 값>
QUEUE_PREFIX=dev-taewoo-
```

DB 비밀번호는 Secrets Manager에서 꺼낸다. 아래 명령은 비밀번호를 화면에 띄우지 않고 클립보드로 복사한다. 그대로 `DB_PASSWORD=` 뒤에 붙여 넣는다.

```powershell
(aws secretsmanager get-secret-value --secret-id freshlink-dev-inventory-db --query SecretString --output text | ConvertFrom-Json).password | Set-Clipboard
```

- 비밀번호는 실행 구성에만 둔다. `application*.yml`, `.env` 같은 레포 파일에 적어 커밋하지 않는다.
- 2의 포트 포워딩 창이 열려 있는 상태에서 실행한다. 로그에 `Started ...Application`이 나오고 Flyway가 테이블을 만들면 성공이다.
- `Communications link failure`: 포트 포워딩 창이 꺼졌거나 RDS가 꺼진 시간이다. `Access denied`: `DB_USERNAME`·`DB_PASSWORD`가 다른 서비스 것이 아닌지 본다.

## 4. 개인 큐

`QUEUE_PREFIX`가 큐 이름 앞에 붙는다. 개인 큐를 쓰면 다른 사람 쪽지를 내 서비스가 가져가지 않는다.

| 큐 | 이태우 (`dev-taewoo-`) | 공용 (`dev-`, dev 클러스터용) |
| --- | --- | --- |
| 명령 (FIFO) | `dev-taewoo-inventory-commands.fifo` | `dev-inventory-commands.fifo` |
| 결과 | `dev-taewoo-inventory-results` | `dev-inventory-results` |
| DLQ | 각각 이름 끝에 `-dlq`(FIFO는 `-dlq.fifo`) | 같음 |

- 3번 받고도 처리에 실패한 쪽지는 DLQ로 옮겨진다.
- PC에서는 공용 큐(`dev-`)를 쓰지 않는다. dev 클러스터의 서비스와 쪽지를 나눠 가져가게 된다.

### 4-1. 내 큐에 INBOUND(입고) 쪽지 보내기

logistics-simulator 없이 inventory-service의 입고 처리를 시험할 때 쓴다. 형식은 [백엔드-공통작업-인수인계.md](백엔드-공통작업-인수인계.md) 쪽지 표를 따른다. `productCode`는 실제 상품 코드로 바꾼다.

```powershell
$id = [guid]::NewGuid().ToString()
@"
{"messageId":"$id","type":"INBOUND","createdAt":"2026-10-16T10:00:00+09:00","storeId":1,"shipmentId":"SHP-TEST-001","items":[{"productCode":"P001","quantity":10,"expiryDate":"2026-10-20"}]}
"@ | Set-Content inbound.json -Encoding Ascii

$q = aws sqs get-queue-url --queue-name dev-taewoo-inventory-commands.fifo --query QueueUrl --output text
aws sqs send-message --queue-url $q --message-body file://inbound.json --message-group-id 1 --message-deduplication-id $id
```

- JSON은 파일(`file://`)로 넘긴다. PowerShell 5.1은 명령줄로 넘긴 JSON의 따옴표를 지운다.
- 그룹 ID는 `storeId`를 문자열로 바꾼 값, 중복 제거 ID는 `messageId`다.
- `MessageId`가 나오면 보낸 것이다. 서비스가 떠 있으면 바로 가져가 처리한다.

### 4-2. DLQ 쪽지 확인하고 다시 보내기

```powershell
# DLQ에 쌓인 개수
$dlq = aws sqs get-queue-url --queue-name dev-taewoo-inventory-commands-dlq.fifo --query QueueUrl --output text
aws sqs get-queue-attributes --queue-url $dlq --attribute-names ApproximateNumberOfMessages

# 내용 보기 (지우지 않으므로 잠시 뒤 다시 DLQ에 보인다)
aws sqs receive-message --queue-url $dlq --query "Messages[].Body"

# 원래 큐로 다시 보내기 (버그를 고친 뒤)
$arn = aws sqs get-queue-attributes --queue-url $dlq --attribute-names QueueArn --query Attributes.QueueArn --output text
aws sqs start-message-move-task --source-arn $arn
aws sqs list-message-move-tasks --source-arn $arn   # Status가 COMPLETED면 끝
```

- 목적지를 안 주면 쪽지가 원래 왔던 큐로 돌아간다.
- 버리려면 `aws sqs purge-queue --queue-url $dlq`(되돌릴 수 없다).
