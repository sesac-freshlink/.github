### BFF 인프라 세팅 (경우님에게 넘김)
- [x] **Cognito 앱 클라이언트 추가** (infra `modules/cognito/main.tf`): 지금 `web` 클라이언트는 시크릿 없는 브라우저용이다. 서버용 `bff` 클라이언트를 새로 만든다. `generate_secret = true`, `explicit_auth_flows = ["ALLOW_ADMIN_USER_PASSWORD_AUTH", "ALLOW_REFRESH_TOKEN_AUTH"]`, `enable_token_revocation = true`, 토큰 기간·`read_attributes`(`custom:storeId` 포함)는 `web`과 같게. 경우님이 프론트를 다 옮길 때까지 `web` 클라이언트는 남겨 두고, 옮긴 뒤 지운다.
- [x] **클라이언트 시크릿 보관**: Terraform이 시크릿을 Secrets Manager(`freshlink-<env>/gateway/cognito`)에 넣는다. 출력(output)에 시크릿을 내보내지 않는다.
- [x] **gateway IRSA 새로 만들기** (`envs/<env>/cluster/main.tf`): 지금 gateway는 AWS를 안 불러서 IRSA가 없다. `modules/irsa`로 gateway 서비스 계정용 Role을 만들고 `cognito-idp:AdminInitiateAuth`를 해당 사용자 풀 ARN에만 허용한다(`SignUp`·`ConfirmSignUp`·`RevokeToken`은 IAM이 필요 없는 공개 API라 시크릿만 있으면 된다).
- [ ] **ArgoCD 루트 값 전달** (`charts/argocd-root` 값): gateway에 IRSA Role ARN, `COGNITO_USER_POOL_ID`, 새 `COGNITO_CLIENT_ID`(bff)를 넘긴다. 토큰 `aud`가 bff 클라이언트 ID가 되므로 gateway 검증 값도 같이 바뀐다(전환하는 날 맞춘다).
  - IRSA Role ARN과 `COGNITO_BFF_CLIENT_ID`는 넘겼다(infra #55). dev는 10/29 전환 완료: gateway 검증 `aud`를 bff로 바꿨다(infra [#58](https://github.com/sesac-freshlink/infra/pull/58)). 경우님 코드가 들어올 때까지 dev 로그인은 안 될 수 있다. prod는 경우님 코드가 main으로 릴리즈될 때 바꾼다.
- [x] **gitops 차트** (`charts/spring-service`): 지금 ExternalSecret은 DB 비밀(`db.secretName`)만 받는다. 일반 비밀을 환경 변수로 넣는 값(예: `extraSecrets`)을 추가해 gateway가 `COGNITO_CLIENT_SECRET`을 받게 하고, `envs/dev·prod/gateway/values.yaml`에 서비스 계정 IRSA 주석과 비밀 이름을 넣는다.
  - 10/29 완료: infra [#55](https://github.com/sesac-freshlink/infra/pull/55)(`bff` 클라이언트, 시크릿 `freshlink-<env>/gateway/cognito`, gateway IRSA `AdminInitiateAuth`, 루트 값 `COGNITO_BFF_CLIENT_ID`·`COGNITO_DOMAIN_URL`·`FRONTEND_URL`), gitops [#10](https://github.com/sesac-freshlink/gitops/pull/10)(`extraSecrets` → `COGNITO_CLIENT_SECRET`, IRSA 주석). dev에서 ExternalSecret 동기화, bff 로그인 `aud`=bff, 갱신, 토큰 취소 확인.

- [x] 바뀌는 흐름 그림(로그인·API 호출·갱신·로그아웃)과 바뀌지 않는 것(member·inventory·order, `UserHeaderFilter` 사용자 헤더).
- [x] 인프라가 준 값: dev·prod 사용자 풀 ID, `bff` 클라이언트 ID, 시크릿이 들어오는 환경 변수 이름(`COGNITO_CLIENT_SECRET`), gateway 서비스 계정 이름과 IRSA로 허용된 Cognito 작업, 가입 후 Lambda가 역할 값 없이 항상 `CUSTOMER`로 넣는다는 것.
- [x] gateway에 추가할 것 목록(아래 경우님 "BFF gateway 로직"과 같은 내용)과 참고할 기존 파일(`security/SecurityConfig.java`, `CognitoJwtValidators.java`, `CognitoProperties.java`, `UserHeaderFilter.java`, 가짜 JWKS 테스트).
- [x] 쿠키·CSRF 규칙(이름, Path, 만료, `HttpOnly; Secure; SameSite=Strict`, `X-Requested-With` 헤더)과 `SECRET_HASH` 계산 방법(HMAC-SHA256(시크릿, 사용자 이름 + 클라이언트 ID)을 Base64).

- [x] 구글 로그인을 BFF 방식으로 할 때의 Hosted UI 주소, 콜백 주소, 코드 교환 방법.

### BFF gateway 로직 (김진아 인수인계 문서를 받아서)
- [x] gateway `build.gradle`에 AWS SDK `software.amazon.awssdk:cognitoidentityprovider`와 `runtimeOnly software.amazon.awssdk:sts`(IRSA 자격 증명용)를 추가한다.
- [x] `AuthController`(`/auth/**`, 외부 주소는 `/api/auth/**`)를 새로 만든다. 라우트로 넘기지 않고 gateway가 직접 처리한다.
  - `POST /auth/login`: `AdminInitiateAuth`(흐름 `ADMIN_USER_PASSWORD_AUTH`, `SECRET_HASH` 포함). 비밀번호가 틀리면 401과 공통 오류 형식.
  - `POST /auth/signup`, `POST /auth/confirm`: Cognito `SignUp`, `ConfirmSignUp`. 역할은 넘기지 않는다. 가입 후 Lambda가 직접 가입은 항상 `CUSTOMER`로 넣는다(`ClientMetadata.role`은 보지 않는다).
  - `POST /auth/refresh`: `AdminInitiateAuth`(흐름 `REFRESH_TOKEN_AUTH`). 리프레시 토큰은 쿠키에서 읽는다.
  - `POST /auth/logout`: `RevokeToken` 후 쿠키 삭제(`Max-Age=0`).
  - `GET /auth/me`: 쿠키의 ID 토큰을 검증해 사용자 정보(userId, role, storeId, email)를 준다. 새로 고침 뒤 로그인 복원에 쓴다.
  - (구글 로그인) `GET /auth/google`: Hosted UI로 리디렉트. `GET /auth/callback`: 받은 코드를 토큰으로 바꿔 쿠키를 굽고 화면으로 리디렉트.
- [x] 쿠키: ID 토큰 `fl_id`(`Path=/api`, 만료 = ID 토큰 만료), 리프레시 `fl_refresh`(`Path=/api/auth`, 만료 = 리프레시 기간). 둘 다 `HttpOnly; Secure; SameSite=Strict`.
- [x] `SecurityConfig`: `BearerTokenResolver`를 바꿔 `Authorization` 헤더가 없으면 `fl_id` 쿠키에서 토큰을 읽게 한다. `/api/auth/login·signup·confirm·refresh·google·callback`은 공개.
- [x] CSRF: 상태를 바꾸는 요청(POST·PUT·PATCH·DELETE)은 `X-Requested-With: freshlink` 헤더가 없으면 403.
- [x] 설정 추가: `freshlink.cognito.user-pool-id`, `client-id`(bff), `client-secret`(환경 변수 `COGNITO_CLIENT_SECRET`, 파일에 쓰지 않는다).

## 참고: BFF 전환 흐름

지금은 브라우저의 Amplify가 Cognito에 직접 로그인하고, 토큰(ID·리프레시)을 **localStorage**에 둔다. 프론트는 ID 토큰을 `Authorization: Bearer`로 붙이고, gateway가 JWKS로 검증한다. BFF로 바꾸면 **로그인·토큰 갱신을 gateway가 대신 하고, 토큰은 브라우저 JS가 읽을 수 없는 HttpOnly 쿠키에만 둔다.** 프론트에서 Amplify(`aws-amplify`)는 완전히 빠진다. 새 서비스를 만들지 않고 gateway를 BFF로 쓴다(CloudFront `/api/*`가 이미 gateway로 가서 같은 주소라 쿠키가 그대로 붙는다).

1. 화면 → `POST /api/auth/login`(이메일·비밀번호) → gateway가 Cognito `AdminInitiateAuth` 호출 → ID·리프레시 토큰을 `Set-Cookie`로 내려 준다. 응답 본문에는 사용자 정보만 준다.
2. 이후 API 요청은 쿠키가 자동으로 붙는다. gateway가 쿠키의 ID 토큰을 지금과 같은 방법(JWKS, iss·aud·token_use)으로 검증하고, `UserHeaderFilter`가 지금처럼 사용자 헤더를 만든다. **뒤쪽 서비스(member·inventory·order·notification)는 바뀌지 않는다.**
3. ID 토큰이 만료되어 401이 나면 화면이 `POST /api/auth/refresh`를 한 번 부르고, gateway가 리프레시 쿠키로 새 ID 토큰을 받아 쿠키를 바꾼다. 그것도 실패하면 "다시 로그인해 주세요".
4. 로그아웃은 `POST /api/auth/logout` → gateway가 Cognito `RevokeToken`으로 리프레시 토큰을 끊고 쿠키를 지운다.

나누는 방법: 인프라(Cognito `bff` 클라이언트, 시크릿, gateway IRSA, ArgoCD·gitops 값, CloudFront 확인)와 인수인계 문서는 김진아, gateway 로직과 프론트 로직은 경우님.
